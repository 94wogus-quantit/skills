# v3.34.0 (2026-04-30)

## run-ralph: PostToolUse force-stop hook 신설 (ralph-loop promise 미감지 우회)

`claude-plugins-official/ralph-loop` 1.0.0 의 `hooks/stop-hook.sh` 가 transcript JSONL 의 control character + last-text-block 추출 위치 문제로 정상 emit 된 `<promise>` 태그를 못 잡고 max-iterations 까지 무한 재주입되는 알려진 한계를 발견했다 (자세한 분석은 사용자 메모리의 `project_ralph_loop_promise_detection_bug.md`). upstream(`anthropics/claude-plugins-public@main`) 의 stop-hook 도 우리 캐시본과 byte-identical (1.0.0 = upstream main, 변경 안 됨) 이라 fix 가 가까운 시일 내에 자동으로 들어올 가능성은 낮다. 우리 plugin 단에서 우회한다.

해결 메커니즘은 단순하다: `choo-choo` Phase 6 의 `rm .ralph/.report-pending` 명령은 이미 "이 run 종료 신호" 로 정의돼 있으니, 같은 명령에 piggyback 해서 ralph-loop state 파일(`.claude/ralph-loop.local.md`) 도 함께 제거하면 다음 Stop 이벤트에서 ralph-loop 의 stop-hook 이 state 파일 부재로 exit 0 → loop 깨끗하게 종료. brittle 한 transcript 파싱 자체를 우회하는 셈.

### Added

- **`plugins/run-ralph/hooks/run-ralph-force-stop.sh`** — PostToolUse hook (matcher: `Bash`). 결정 로직:
  1. `tool_name` ≠ `Bash` → 즉시 `exit 0` (silent)
  2. `tool_input.command` 에 `rm ... .ralph/.report-pending` 패턴 없음 → `exit 0`
  3. `${CLAUDE_PROJECT_DIR}/.claude/ralph-loop.local.md` 존재 시 → `rm` + stderr 한 줄 로그 + `exit 0`
  4. 존재 안 하면 → idempotent silent no-op
  - `set -euo pipefail` + `${CLAUDE_PROJECT_DIR}` 패턴 (CWD-independent) 으로 기존 hooks 와 일관성 유지.
  - smoke 검증 4종 (비-Bash / 트리거 명령 아님 / 트리거 명령 + state 부재 / 트리거 명령 + state 존재) 모두 통과.
- **`plugins/run-ralph/hooks/hooks.json`** — `PostToolUse.Bash` matcher entry 추가. 기존 `Stop` block (report-gate, record-gate) 은 그대로 보존. description 한 줄 보강.

### Changed

- **`plugins/run-ralph/skills/choo-choo/SKILL.md`** — Phase 4 Iteration Workflow block 의 판정 게이트 절에 **promise emit position rule** 단락 신설. 핵심 문구:
  > "`<promise>...</promise>` MUST be the **absolute last text block** of the final iteration's message. NO text, tool call, acknowledgment, recap, or any other content after the promise tag."
  - 이유 인용: ralph-loop 1.0.0 stop-hook 이 마지막 assistant text block 만 perl-extract 하여 `<promise>` 태그를 찾기 때문 — Worker 가 promise 뒤 한 줄이라도 더 출력하면 hook 이 못 잡고 loop 가 max-iterations 까지 무한 재주입.
  - v1.3.0 의 force-stop hook 은 1차 fallback 이고, 이 position rule 이 1차 방어선. 둘 다 어겨야 무한 루프.
  - 판정 게이트 step 5-b 에 force-stop hook 의 trigger 메커니즘 한 줄 인라인 (sentinel rm 이 동시에 state 파일도 정리한다는 점 명시).
- **`plugins/run-ralph/.claude-plugin/plugin.json`** — `version`: `1.2.0` → **`1.3.0`** (cache invalidation). description 갱신 (PostToolUse force-stop hook + promise position rule 명시).
- **`.claude-plugin/marketplace.json`** — `metadata.version`: `3.33.0` → **`3.34.0`** (marketplace 카탈로그 버전 — `/marketplace refresh` 트리거).
- **`CHANGELOG.md`** — v3.x 인덱스 표 첫 행에 v3.34.0 row 삽입.
- **`CLAUDE.md`** — Repository Structure 트리의 run-ralph hooks 설명 갱신 (PostToolUse hook 추가). Notes 섹션 `**run-ralph (1.2.0)**` → `**run-ralph (1.3.0)**` + hook 카운트 갱신 (2 Stop → 2 Stop + 1 PostToolUse). 최근 ADR 표 첫 행에 v3.34.0 요약 추가.
