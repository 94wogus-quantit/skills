# Fix Discussion

## ⚠️ CRITICAL LANGUAGE POLICY

**DEFAULT LANGUAGE: KOREAN (한국어)**

모든 출력, 코멘트, 커뮤니케이션은 **한국어**로 작성해야 합니다.

---

## Overview

GitLab MR의 discussion에서 지적한 문제를 **코드 수정 → 답글 → resolve** 순서로 처리합니다.

**주요 기능**:
- 🔧 **코드 수정**: discussion에서 지적한 코드 문제 수정
- 💬 **답글 작성**: 수정 내용을 설명하는 답글 자동 생성
- ✅ **Resolve**: discussion을 resolved 상태로 변경
- 📝 **변경 추적**: 모든 수정 사항 요약 제공

---

## When to Use

**✅ 사용할 때:**
- `list-discussions`로 확인한 discussion을 수정할 때
- 리뷰어의 피드백을 반영할 때
- 여러 discussion을 일괄 처리할 때

**❌ 사용하지 않을 때:**
- discussion 내용이 명확하지 않을 때 (먼저 리뷰어와 논의)
- 수정이 필요 없는 의견성 코멘트일 때

## Workflow

### Phase 0: Discussion 정보 확인

**0-1. 입력 정보 확인**

필요한 정보:
- MR IID (또는 현재 브랜치에서 자동 탐지)
- Discussion ID (또는 "모두" 선택)

**0-2. Discussion 상세 조회**

```bash
# 특정 discussion 상세 정보
glab api "projects/:fullpath/merge_requests/${MR_IID}/discussions/${DISCUSSION_ID}" | jq '.'
```

추출할 정보:
- `notes[0].body`: 원본 코멘트 (수정 가이드)
- `notes[0].position.new_path`: 파일 경로
- `notes[0].position.new_line`: 라인 번호
- `notes[0].position.old_line`: 이전 라인 (있는 경우)

---

### Phase 1: 코멘트 분석

**1-1. 코멘트 내용 파싱**

코멘트에서 다음 정보 추출:
- **문제 유형**: Critical, High, Medium 등
- **문제 설명**: 무엇이 문제인지
- **제안 코드**: 수정 방향 (있는 경우)

**1-2. Sequential Thinking으로 분석**

```typescript
mcp__plugin_workflow-bundle_sequential-thinking__sequentialthinking({
  thought: "Discussion 분석: 이 코멘트가 지적하는 문제는 무엇인가? 어떤 코드 변경이 필요한가?",
  thoughtNumber: 1,
  totalThoughts: 3,
  nextThoughtNeeded: true
})
```

**1-3. 수정 계획 수립**

```markdown
## 수정 계획

**파일**: src/api/user.ts
**라인**: 45
**문제**: SQL Injection 위험
**수정 방향**: Prepared Statement 사용

**Before**:
```typescript
const query = `SELECT * FROM users WHERE id = ${userId}`;
```

**After**:
```typescript
const query = 'SELECT * FROM users WHERE id = ?';
const result = await db.execute(query, [userId]);
```
```

### Phase 2: 코드 수정

**2-1. 파일 읽기**

```typescript
// 해당 파일 읽기
Read({ file_path: "/path/to/project/src/api/user.ts" })
```

**2-2. 코드 수정 실행**

```typescript
// Edit 도구로 수정
Edit({
  file_path: "/path/to/project/src/api/user.ts",
  old_string: "const query = `SELECT * FROM users WHERE id = ${userId}`;",
  new_string: "const query = 'SELECT * FROM users WHERE id = ?';\nconst result = await db.execute(query, [userId]);"
})
```

**2-3. 수정 확인**

수정 후 해당 라인 다시 읽어서 확인

---

### Phase 3: 답글 작성

**3-1. 답글 내용 생성**

```markdown
✅ **수정 완료**

**변경 사항**:
- Prepared Statement 패턴으로 변경
- 파라미터 바인딩 적용

**수정된 코드**:
```typescript
const query = 'SELECT * FROM users WHERE id = ?';
const result = await db.execute(query, [userId]);
```

---
🤖 Generated by Claude Code
```

**3-2. GitLab API로 답글 등록**

```bash
# Discussion에 답글 추가
glab api --method POST \
  "projects/:fullpath/merge_requests/${MR_IID}/discussions/${DISCUSSION_ID}/notes" \
  -f body="✅ **수정 완료**

**변경 사항**:
- Prepared Statement 패턴으로 변경
- 파라미터 바인딩 적용

---
🤖 Generated by Claude Code"
```

---

### Phase 4: Discussion Resolve

**4-1. Discussion Resolve 처리**

```bash
# Discussion resolve
glab api --method PUT \
  "projects/:fullpath/merge_requests/${MR_IID}/discussions/${DISCUSSION_ID}" \
  -f resolved=true
```

**4-2. Resolve 확인**

```bash
# resolve 상태 확인
glab api "projects/:fullpath/merge_requests/${MR_IID}/discussions/${DISCUSSION_ID}" \
  | jq '.notes[0].resolved'
```

## Batch Processing

여러 discussion을 일괄 처리할 때:

**1. 모든 unresolved discussion 처리**

```
"모든 discussion 수정해줘"
```

**2. 특정 discussion만 선택**

```
"Discussion #1, #3만 수정해줘"
```

**3. 특정 파일의 discussion만**

```
"src/api/*.ts 파일의 discussion만 수정해줘"
```

### 일괄 처리 워크플로우

```
for each discussion in selected_discussions:
  1. 코멘트 분석
  2. 코드 수정
  3. 답글 작성
  4. Resolve
  5. 결과 기록
end

6. 전체 요약 출력
7. git commit 안내
```

## Error Handling

### 코드 수정 실패

```markdown
⚠️ Discussion #1 코드 수정 실패

**원인**: 해당 코드가 이미 변경되었거나 찾을 수 없음

**원본 위치**: src/api/user.ts:45
**찾으려 한 코드**:
```typescript
const query = `SELECT * FROM users WHERE id = ${userId}`;
```

**다음 단계**:
1. 파일을 직접 확인: `src/api/user.ts`
2. 수동으로 수정 후 다시 시도
3. 또는 이 discussion 스킵
```

### API 권한 오류

```markdown
❌ Discussion resolve 실패

**원인**: API 권한 부족 또는 이미 resolved 상태

**확인 사항**:
1. glab 인증 상태: `glab auth status`
2. Discussion 현재 상태 확인
3. 해당 MR에 대한 쓰기 권한 확인
```

## Best Practices

### 코드 수정 시

1. **최소 변경 원칙**: 지적된 부분만 수정
2. **컨텍스트 유지**: 주변 코드 스타일 따르기
3. **테스트 고려**: 수정이 테스트에 영향 주는지 확인

### 답글 작성 시

1. **명확한 설명**: 무엇을 왜 변경했는지
2. **코드 포함**: 변경된 코드 스니펫 첨부
3. **간결함**: 불필요한 장문 피하기

### Resolve 시

1. **확인 후 Resolve**: 실제로 수정이 완료되었을 때만
2. **부분 수정 시**: 답글에 "부분 수정" 명시 후 resolve
3. **논의 필요 시**: resolve하지 않고 답글로 질문

## Integration

### 전체 워크플로우

```
1. mr-review (CI) → MR에 discussion 생성
2. list-discussions → discussion 목록 확인
3. fix-discussion → 코드 수정 + 답글 + resolve
4. git commit & push → 변경사항 반영
5. MR 머지 가능 상태
```

### 관련 Skills

- **list-discussions**: discussion 목록 조회 (선행 skill)
- **mr-review**: MR 코드 리뷰 및 discussion 생성
