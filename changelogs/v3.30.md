# v3.30.0 (2026-04-27)

## run-ralph(choo-choo) 스킬 일반화 + per-run 산출물 격리

run-ralph 플러그인의 choo-choo 스킬이 두 가지 framing 버그를 동시에 해소.

1. 스킬 명세가 "코드 변경 작업"에 편향된 어휘로 도배되어 있어, 메타/설계/통합/문서 작업 요청을 받으면 Claude가 task taxonomy 매칭에 실패하고 "out of scope"로 거부하는 경향. 사용자 정정에 매번 의존하는 구조였음.
2. 모든 run의 산출물(`prompt`, `review-{N}`, `qa-{N}`, custom-role logs)이 `.ralph/` 평면에 저장되어, 두 번째 run 시작 시 이전 run의 `review-1.md`/`qa-1.md`가 덮여 과거 로그를 잃음.

### Why this matters

- **거부 시나리오 차단**: 이전엔 `/run-ralph:choo-choo "두 스킬 통합 설계해줘"` 같은 메타 요청이 들어오면 Claude가 "Ralph Loop은 코드 변경 작업이라 out of scope"로 거부하는 일이 반복됨. SKILL의 첫 30줄 안에 4-row scope 표 + 명시적 "Do not refuse" 지시가 들어가 더 이상 발생하지 않음.
- **메타 작업도 게이트가 의미 있게 작동**: Example 4가 보여주듯 코드 0줄 변경에도 Reviewer/QA + Domain-Expert + Reader-Persona + 3-level AC가 자기 역할을 함. choo-choo의 본질이 "Worker 자기 판정 방지 + 단계적 검증"이지 "코드에 한정된 검증"이 아님이 문서적으로도 입증됨.
- **여러 run의 로그 추적 가능**: `.ralph/auth-jwt-merge/review-3.md`, `.ralph/skill-A-B-merge-adr/review-1.md`처럼 슬러그로 자동 격리. 며칠/몇 주 후 "그때 그 리팩토링 iteration 5 reviewer가 뭐라고 했지?"를 정확히 찾아볼 수 있음.

## wf + wf2 통합 → new wf v3.30.0 + choo-choo Auto-dispatch

`plugins/wf/` (Pack A: 현 wf 플러그인)와 `~/Project/arkraft/.claude/skills/wf2-*` (Pack B: arkraft의 별도 스킬 팩) 두 워크플로우 책임이 부분 중복되며 각자 다른 구조적 약점을 가지고 있었다. v3.30에서 두 팩의 강점을 합쳐 단일 wf 플러그인으로 통합하고, `run-ralph:choo-choo`에 task 복잡도 자동 분류 dispatch를 추가.

**Pack A 강점**: First Principles methodology, Evidence Trail, `git_local_server.py` (12 git tools), `requirement-validator` agent (AC 4-mode 추적), 1391-LOC `record` skill (matklad ARCH, Serena 메모리, 멀티 문서 동기화).
**Pack A 약점**: `plan/SKILL.md` Phase 3가 Worker 자기검토 루프 (`Step A → B → C → D`, `REPEAT until zero issues`) — 자기승인 편향, 무한 iteration 위험. QA acceptance 게이트 부재. skill 간 외부 review gate 없음.
**Pack B 강점**: 외부 review agent (`wf2-review-{analyze,plan,record}`)가 LGTM/REVISE machine-parseable verdict 발행, `wf2-review-gate.sh` PostToolUse(Write) 훅으로 자기승인 차단, 독립 `wf2-qa-agent`.
**Pack B 약점**: git MCP 없음, `record` 등가 skill 없음, `requirement-validator` 없음, dispatch 없음.

→ **new wf = Pack A 백본 (git MCP / requirement-validator / record) + Pack B 게이트 (외부 review agents / hook / qa skill)**

### Why this matters

- **자기승인 편향 차단**: pre-v3.30 plan/SKILL.md는 Worker가 자기 plan을 review하는 self-loop이라 인지 편향 + 무한 iteration 위험이 있었음. v3.30에선 plan을 Write하면 PostToolUse hook이 외부 wf-review-plan agent를 자동 spawn하고 LGTM verdict이 나올 때까지 Write→Review 사이클 — 외부 가이드만 인정.
- **Acceptance gate 신설**: pre-v3.30 execute는 자기 테스트 auto-recovery만 있었고 "tests pass ≠ requirements met" 갭이 있었음. v3.30 Phase 7.5 wf:qa 독립 spawn으로 reproduction scenario + 성공 기준 재실행 → PASS 받아야 record 진행.
- **Dispatch 자동화**: 사용자가 "이 task가 wf 풀 파이프라인 거쳐야 할지 / 그냥 ralph 직행할지" 매번 결정할 필요 없음. choo-choo Phase 1.5가 file count, JIRA-ID, schema/API 변경, 새 파일/의존성 등 신호로 자동 분류. trivial은 ralph 직행 (오버헤드 회피), full은 wf 5단계 → ralph로 (품질 보장).
- **두 강점 합치기 (사용자 의도)**: 사용자 명시적 답변 — "둘다 분석해서 둘의 장점을 강화하고 약점은 최소화하는 식으로 가고 싶은디? 즉 new wf가 생기는거고 기존 wf, wf2는 이걸로 통합되는거지!" — 그대로 구현.
