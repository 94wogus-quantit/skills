# v3.30.0 (2026-04-27)

## run-ralph(choo-choo) 스킬 일반화 + per-run 산출물 격리

run-ralph 플러그인의 choo-choo 스킬이 두 가지 framing 버그를 동시에 해소.

1. 스킬 명세가 "코드 변경 작업"에 편향된 어휘로 도배되어 있어, 메타/설계/통합/문서 작업 요청을 받으면 Claude가 task taxonomy 매칭에 실패하고 "out of scope"로 거부하는 경향. 사용자 정정에 매번 의존하는 구조였음.
2. 모든 run의 산출물(`prompt`, `review-{N}`, `qa-{N}`, custom-role logs)이 `.ralph/` 평면에 저장되어, 두 번째 run 시작 시 이전 run의 `review-1.md`/`qa-1.md`가 덮여 과거 로그를 잃음.

### Changed

- **`plugins/run-ralph/skills/choo-choo/SKILL.md`** — 일반화 framing
  - description: "ANY iterative work — code changes, design documents, skill/workflow integrations, architectural decisions, documentation, refactoring" 명시 + "general iterative framework, not a code-only tool" 명시
  - 본문 상단에 **"Scope" 콜아웃** 신규 (4-row 표 + Out-of-scope + "Do not refuse a request as 'not a code change'" instruction)
  - Phase 1 Clarify 표: 메타 예시 2 row 추가 ("두 스킬 통합해줘" / "아키텍처 결정해줘")
  - Phase 2 task-type matrix: **Design / Meta** + **Integration / Migration** row 신설
  - Phase 2 Custom role triggers: **Domain-Expert** 트리거 추가
  - Phase 3 L2 SKIP 룰: `no_design_artifact` 조건 추가 (1-file 설계 문서가 fake N/A로 떨어지는 회귀 차단)
  - Phase 3 L3 트리거 목록: ADR / design docs 명시
  - Phase 4 Repo-specific constraints 템플릿: design/meta-work 제약 예시 추가

- **`plugins/run-ralph/skills/choo-choo/SKILL.md`** — per-run 산출물 격리
  - **저장 컨벤션**: 평면 `.ralph/<slug>-prompt.md` / `.ralph/review-{N}.md` → 서브디렉토리 `.ralph/<slug>/prompt.md` / `.ralph/<slug>/review-{N}.md` / `.ralph/<slug>/qa-{N}.md` / `.ralph/<slug>/<custom>-{N}.md`
  - **Sentinel은 그대로** `.ralph/.report-pending` (top-level): 한 Claude 세션 내 동시 run은 없으므로 session-level 마커가 충분, hook 변경 불필요
  - Slug rule 변경: 이전엔 파일명 (`*-prompt.md`), 이제 디렉토리명 (`<slug>/`)
  - Iteration Workflow 블록에 `{RUN_DIR}` placeholder 도입 (`{PROJECT_ROOT}/.ralph/<slug>`), Reviewer/QA spawn에 `output_path` 명시 인자 추가
  - Phase 5 Execute step 1: `mkdir -p` + 슬러그 디렉토리 생성 후 `prompt.md` 작성
  - Phase 6 evidence collection / 산출물 위치 모두 per-slug 경로로 sync

- **`plugins/run-ralph/skills/choo-choo/references/team-composition.md`**

  - 산출물 경로 표기 `.ralph/<slug>/...`로 sync

  - Example 1~3: 산출물 경로 모두 `.ralph/<slug>/` 형태로 갱신, slug 예시도 `auth-jwt-merge` / `alpha-pool-redis` / `topic-card-skeleton`로 정리

  - 주석에 "sentinel은 top-level — per-run 서브디렉토리에 들어가지 않음" 명시
  - reason 메시지의 review/qa 경로 힌트를 `.ralph/<slug>/...` 형태로 sync (slug는 `ls .ralph/`로 확인하라고 안내)

### Backward Compatibility

- **이전 평면 파일** (`.ralph/review-N.md` 등): 손대지 않음. 새 run부터 `.ralph/<slug>/` 하위로 자동 분리. 사용자 마이그레이션 액션 불필요.
- **Stop hook 동작**: sentinel 위치 동일 (`.ralph/.report-pending`), decision logic 동일. 진행 중인 Ralph Loop이 있다면 그대로 동작.
- **Breaking changes**: 없음. plugin.json minor bump으로 충분.

### Why this matters

- **거부 시나리오 차단**: 이전엔 `/run-ralph:choo-choo "두 스킬 통합 설계해줘"` 같은 메타 요청이 들어오면 Claude가 "Ralph Loop은 코드 변경 작업이라 out of scope"로 거부하는 일이 반복됨. SKILL의 첫 30줄 안에 4-row scope 표 + 명시적 "Do not refuse" 지시가 들어가 더 이상 발생하지 않음.
- **메타 작업도 게이트가 의미 있게 작동**: Example 4가 보여주듯 코드 0줄 변경에도 Reviewer/QA + Domain-Expert + Reader-Persona + 3-level AC가 자기 역할을 함. choo-choo의 본질이 "Worker 자기 판정 방지 + 단계적 검증"이지 "코드에 한정된 검증"이 아님이 문서적으로도 입증됨.
- **여러 run의 로그 추적 가능**: `.ralph/auth-jwt-merge/review-3.md`, `.ralph/skill-A-B-merge-adr/review-1.md`처럼 슬러그로 자동 격리. 며칠/몇 주 후 "그때 그 리팩토링 iteration 5 reviewer가 뭐라고 했지?"를 정확히 찾아볼 수 있음.
