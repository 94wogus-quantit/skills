# v3.23.0 - Evidence Trail 기능 추가

**날짜**: 2026-01-30

## 개요

analyze/plan 스킬 실행 시 수집한 context와 사고 과정(Sequential Thinking)이 최종 산출물(REPORT, PLAN)에 명시적으로 표현되도록 "Evidence Trail" 기능을 추가.

## Added

### analyze 스킬
- **Evidence Trail Rules** 공통 섹션 추가 (Phase 1~2 사이)
  - Sources Collected, Thinking Process, Investigation Results 기록 규칙 정의
- Phase 2 (Context Gathering): 수집 소스 Evidence Log 기록 지시
- Phase 3 (First Principles): 가정/사실 분류 결과 기록 지시
- Phase 4 (Hypothesis Generation): 가설 평가 결과 기록 지시
- Phase 5 (Codebase Investigation): 조사 파일/심볼/패턴 기록 지시
- Phase 8 (Report Generation): Evidence Trail 섹션 포함 지시

### report_template.md
- **Evidence Trail** 섹션 추가 (Summary 뒤, Context 앞)
  - 수집한 소스 테이블 (소스 유형, 파일/도구, 수집 목적, 핵심 발견)
  - 사고 과정 요약 (Phase 3: 가정/사실, Phase 4: 가설, Phase 5: 코드 조사)

### plan 스킬
- Step 1 (Context Gathering): Context Log 테이블 기록 지시
- Step 2 (Requirement Questioning): 요구사항 질의 결과 기록 지시
- Step 3 (Deletion Pass): 삭제 항목/이유 기록 지시
- Step 4 (Simplification): 단순화 결과 기록 지시
- Step 7 (Save Plan): Context & Reasoning 섹션 포함 지시

### plan_template.md
- **Context & Reasoning** 섹션 추가 (Constraints 뒤, Task Breakdown 앞)
  - 수집한 소스 테이블
  - 사고 과정 (5-Step Algorithm 각 단계 요약)

### review_checklist.md
- **12번 섹션: Evidence Trail Quality** 추가
  - Context & Reasoning 섹션 존재 검증
  - 수집 소스 테이블 비어있지 않은지 검증
  - 사고 과정 추적 가능성 검증
- 체크리스트 범위 1-11 → 1-12로 업데이트

## 변경 동기

사용자가 스킬 실행 후 어떤 정보를 수집했고, 어떤 사고 과정을 거쳐 결론에 도달했는지 추적할 수 없었음. REPORT/PLAN 문서가 결론만 담고 있어 빈약한 느낌. Evidence Trail로 "왜 이런 결론에 도달했는지" 추적 가능하도록 개선.
