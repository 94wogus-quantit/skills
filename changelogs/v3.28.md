# v3.28.0 - notify 플러그인: macOS 음성+팝업 알림

**날짜**: 2026-02-23
**브랜치**: `feature/notify-plugin`

---

## 요약

Claude Code 작업 완료(`Stop`) 또는 사용자 확인 요청(`Notification`) 시 macOS 팝업 알림과 음성(TTS)을 자동 발송하는 `notify` 플러그인을 신규 추가합니다. 단순 "완료" 대신 실제 작업 내용을 4단계 fallback으로 추출하여 음성으로 읽어줍니다.

---

## Added

- **`plugins/notify/`** 신규 플러그인 추가 (훅 전용 - MCP·스킬·에이전트 없음)
  - `hooks/notify.sh`: 메인 알림 스크립트
    - stdin JSON 파싱: Python3 단일 호출 + JSON 출력 (pipe 구분자 문제 방지)
    - **4단계 content fallback**: Notification message → Stop reason → transcript_path 파싱 (JSONL→텍스트 패턴) → history.jsonl user prompt
    - **osascript 보안**: Python `subprocess.Popen(['osascript', '-e', script])` 패턴 (heredoc 대신) → shell injection 완전 차단
    - **UTF-8 안전 truncation**: `head -c` 바이트 절단 대신 Python `[:100]` 문자 단위
    - **Yuna 음성**: `say -v "Yuna"` 한국어 Premium Neural TTS, 미설치 시 시스템 기본 음성 fallback
    - **디버그 덤프**: 첫 실행 시 `/tmp/claude_notify_debug.json` 생성 (stdin 포맷 확인용)
    - 항상 `exit 0` (Claude 블로킹 방지)
  - `hooks/hooks.json`: Stop + Notification 훅 설정 (`timeout: 10`, `bash ${CLAUDE_PLUGIN_ROOT}/hooks/notify.sh`)
  - `.claude-plugin/plugin.json`: 플러그인 메타데이터 (name=notify, v1.0.0)
  - `README.md`: 설치, 음성 설정(Yuna/Siri 불가 이유), 디버그 방법, 동작 방식 안내

- **`.claude-plugin/marketplace.json`**: `notify` 플러그인 등록 (9개 → 10개), 버전 3.27.0 → 3.28.0

## 기술적 결정사항

### 훅 전용 최소 설계 (Hooks-only Plugin)

**결정**: MCP 서버·스킬·에이전트 없이 훅(`Stop` + `Notification`)만으로 구성.

**이유**: 알림 기능은 Claude 작업 완료 후 비동기로 발송하면 충분. MCP나 스킬은 필요 없는 과잉 설계. Idiot Index: ~1.5x (최소 설계).

### osascript 실행 방식: Python subprocess (heredoc 대신)

**문제**: Unquoted heredoc에서 `$NOTIFY_MSG` 내 backtick이 shell에 의해 명령으로 실행됨:
```bash
# 취약한 코드
osascript << APPLESCRIPT
display notification "$NOTIFY_MSG"  # backtick injection 가능
APPLESCRIPT
```

**해결**: Python `subprocess.Popen(['osascript', '-e', script])` + `sys.argv`로 값 전달:
```python
# shell interpretation 없음, 완전히 안전
subprocess.Popen(['osascript', '-e', script], stdout=DEVNULL, stderr=DEVNULL)
```

### AppleScript 문자열 이스케이핑: `"` → `'` 치환

**결정**: AppleScript string에서 `"` 를 `'`로 단순 치환 (복잡한 backslash escape 대신).

**이유**: AppleScript는 `\"`를 지원하지 않음. `"` → `'` 치환이 가장 단순하고 안전한 방법.

### reason 필드 1.5차 fallback

**결정**: Stop 이벤트 stdin의 `reason` 필드를 transcript_path 파싱 전에 시도 (1.5차).

**이유**: `reason` 필드는 Claude가 직접 제공하므로 transcript 파싱보다 신뢰도 높음. 빠른 응답 가능.

### JSON 파싱 단일 Python 호출 + 4회 추출

**결정**: stdin을 Python3 1회로 파싱하여 JSON 출력 → 각 필드를 별도 Python 호출로 추출 (총 5회).

**이유**: `|` 구분자 방식은 transcript_path에 `|` 포함 시 오작동 위험. JSON 중간 포맷이 가장 안전.

## 알려진 제한사항

- **macOS 전용**: `osascript`(팝업)와 `say`(TTS)는 macOS에서만 작동
- **transcript_path 포맷 미확인**: JSONL vs 텍스트 포맷이 Claude Code 버전마다 다를 수 있음 → 방어적 이중 파싱 적용
- **알림 권한 필요**: macOS 시스템 환경설정에서 알림 허용 필요 (TTS는 권한 불필요)
- **Yuna 음성 별도 설치 필요**: 시스템 환경설정 → 접근성 → 음성 콘텐츠에서 다운로드
