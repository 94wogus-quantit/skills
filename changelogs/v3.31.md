# v3.31.0 (2026-04-27)

## run-ralph: record harness 강화 + Phase 1.5 dispatch cache invalidation

v3.30.0에서 `choo-choo` Phase 1.5 (wf 5-skill auto-dispatch)와 `wf` 5-skill 통합을 main에 머지했지만, **`run-ralph` plugin.json의 version이 1.1.0 그대로**라 사용자 측 marketplace cache가 invalidation되지 않아 옛 1.1.0 SKILL.md (Phase 1.5 없음)이 그대로 사용되고 있었다. v3.31.0은 두 문제를 동시에 해소한다.

1. **plugin.json version bump**로 cache 강제 갱신.
2. **`wf:record` 누락 차단 Stop hook 신설** (가장 흔한 harness-failure: "코드 변경 + CHANGELOG 미수정" 통제).

### Added

- **`plugins/run-ralph/hooks/run-ralph-record-gate.sh`** — Stop hook (3.7KB, 95 lines). 결정 로직:
  1. `/ralph-loop` 진행 중 → defer
  2. `.ralph/.record-pending` sentinel 부재 → 무관
  3. branch가 `origin/{base}` 대비 commits 0 → 아무 obligation 없음
  4. ahead-commits가 doc-only (`*.md` / `changelogs/` / `.ralph/` / `docs/`) → silent (ADR/design 작업 정상 통과)
  5. ahead-commits에 `CHANGELOG.md` 또는 `changelogs/v*.md` 변경 있음 → docs 이미 OK
  6. otherwise → block + Korean inject ("`Skill(wf:record)` 호출하거나 `rm` sentinel + Phase 6 보고서에 정당화")
  - `set -e` OFF + 모든 git 호출 fallback — non-git directory에서도 silent exit 보장 (smoke 검증)
  - Detection: `git symbolic-ref refs/remotes/origin/HEAD` → `origin/main` → `origin/master` 순으로 base branch 자동 감지
- **`plugins/run-ralph/hooks/hooks.json`** — Stop matcher에 record-gate 등록 (report-gate 다음 순서). description 갱신.

### Changed

- **`plugins/run-ralph/.claude-plugin/plugin.json`** — `version`: `1.1.0` → **`1.2.0`** (cache invalidation trigger). description에 v1.2 변경사항 명시 (Phase 1.5 wf auto-dispatch + record-gate Stop hook).
- **`plugins/run-ralph/skills/choo-choo/SKILL.md`**:
  - **Phase 5 step 2** — `.ralph/.report-pending` 단일 sentinel touch → `.report-pending` + `.record-pending` 두 sentinel 동시 touch. 두 게이트의 의도/제거 책임 분리 설명 단락 추가.
  - **Phase 6 "Order within the final message"** — 4-step 흐름으로 확장:
    - 1. Phase 6 보고서 작성
    - 2. record decision (코드 변경 있으면 `Skill(wf:record)` 호출, doc-only면 sentinel 직접 제거 + 정당화 로깅)
    - 3. `rm .ralph/.report-pending`
    - 4. promise emit
    - + "두 게이트 모두 있는 이유" 콜아웃 (report=human-readable / record=project-doc-sync, orthogonal)
  - **Stop hook safety nets 섹션** — 단일 hook 설명에서 "(1) report-gate / (2) record-gate" 두 hook 구조로 재구성. 각 hook의 결정 로직 + sentinel lifecycle + disable 방법 정리.
- **`.claude-plugin/marketplace.json`** — `metadata.version`: `3.30.0` → **`3.31.0`** (marketplace 카탈로그 버전 — `/marketplace refresh` 트리거).

### Backward Compatibility

- **0 breaking changes.** 기존 사용자가 현재 진행 중인 ralph 세션은 옛 1.1.0 SKILL을 따라 동작 — `.record-pending` sentinel이 없으므로 record-gate hook은 silent exit (조건 1).
- 새 1.2.0이 cache에 들어온 후 신규 ralph 세션부터 `.record-pending` sentinel이 자동 touch되며 게이트가 활성화.
- record-gate는 git diff 자체 검사로 false-positive 차단 — doc-only / experiment-only 작업은 sentinel이 있어도 silent 통과 (조건 4-5). 사용자 spam 위험 낮음.
- non-git directory에서 Claude Code 사용 시 hook은 `cd` 실패 → silent exit. 안전장치 검증됨.

### Why this matters

- **cache invalidation 누락**: v3.30.0 main에 Phase 1.5 dispatch 코드가 들어갔지만 plugin.json 버전이 안 올라가서 사용자 cache는 옛 SKILL을 그대로 사용 중. `/plugin` 명령어가 "already at the latest version (1.1.0)"이라고 표시 → choo-choo 호출해도 wf 자동 활용 안 함. 1.2.0 bump가 이 문제를 해소.
- **record 누락이 가장 흔한 실패 모드**: 코드 변경 → 테스트 통과 → "다 됐다"고 인지하고 세션 종료 → CHANGELOG 갱신 누락. 다음 세션에서 git log를 보면 "이 commit이 뭐였더라" 의문, README와 코드 drift. record-gate가 origin 대비 commit 검사 + CHANGELOG 변경 검사로 이 시나리오를 mechanical하게 차단.
- **사용자 의도 100% 매칭**: "record 보면 항상 놓칠때가 많은데 기능 구현까지 하고 문서화가 마무리가 잘 안되는거지. 이 문서화에 대해서 혹시 뭔가 hook이나 이런거로 하네스 강화 가능한가?" — 정확히 그것.
