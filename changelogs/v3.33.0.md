# v3.33.0 (2026-04-27)

## blogpost plugin 신규 — multi-agent 블로그 작성 + 이미지 큐레이션 + S3 sync

`/blogpost:create <토픽>` 한 번이면 자료 조사부터 S3 업로드까지 자동화하는 신규 plugin. wogus-plugins marketplace를 8 → **9 plugins**로 확장.

### Why a 6-agent pipeline (4-agent 풀구성 + image-curator + html-renderer)

블로그 한 편을 쓰는 일을 단일 LLM 호출로 처리하면 두 가지 실패 모드가 같이 나온다: **자료 부족인데 그럴듯한 글을 써버림** + **이미지가 없거나 라이선스가 불분명**. 둘은 다른 종류의 검증 회로가 필요하므로 책임을 분리:

- **researcher** (자료 수집) ↔ **research-reviewer** (자료 충분성 판정 — MORE_NEEDED/OK)
- **writer** (초안) ↔ **writing-reviewer** (자료 인용 + 이미지 배치 판정 — RESEARCH_GAP/IMAGE_GAP/OK)
- **image-curator** — CC 라이선스 강제 + 출처 metadata.json 기록 전담
- **html-renderer** — markdown→HTML 1:1 변환 금지, figure/figcaption + callout + section semantics 부여 후 `_render/body.html` 산출. Jinja layout은 `render.py`가 wrap만.

각 reviewer는 binary/tri-state 판정만 내고 직접 수정하지 않음 — orchestrator가 verdict 보고 다음 단계 결정. iteration cap (research 5 / writing 6) 안에 수렴 못 하면 강제 진행하고 사용자에게 남은 gap 노출.

### Why bucket/prefix only in settings

`~/.claude/blogpost.local.md` 의 frontmatter는 **`bucket`과 `prefix` 두 키만**. region/CDN/저자 메타는 v1.0.0에서 의도적으로 제외. 이유:

- bucket/prefix만으로 S3 sync + public URL 패턴 모두 도출 가능 (`https://<bucket>.s3.amazonaws.com/<prefix>/<folder>/index.html`)
- 추가 필드는 사용자가 매번 신경써야 하는 설정 부담을 늘림. 필요해지면 후속 버전에서 추가
- "global 설정"의 의도와 정렬: `~/.claude/` 위치 자체가 사용자별 / repo-independent 라는 신호

### Why folder-level S3 sync (per-blog directory)

업로드 단위가 폴더(아니라 개별 파일)인 이유는 **update 워크플로우 단순성**. `/blogpost:update <folder>`는 `aws s3 sync` 양방향만으로 round-trip이 성립하므로 파일별 변경 추적 / merge 로직 필요 없음. v1.0.0은 사용자가 로컬에서 수동 편집한 뒤 같은 명령을 다시 실행하면 자동 재렌더 + 재업로드. 로컬 에디터 자동 통합은 의도적으로 v2 이후로 미룸.

업로드 시 `_source/`, `_render/`, `review-history/`는 제외 (작업 산출물 — 호스팅에 불필요). `초안.md` / `image/` / `metadata.json` / `outline.md` / `index.html`만 S3에 올라감.

### Added

- **`plugins/blogpost/`** 신규 plugin (v1.0.0):
  - `.claude-plugin/plugin.json` — name `blogpost` (8자), version 1.0.0
  - `README.md` — 설치 / 설정 / 사용 / 폴더 구조 / 라이선스 정책 / 트러블슈팅 / 스모크 테스트 / 스코프 외
  - **6 agents** (`agents/`):
    - `blogpost-researcher.md` — web fetch + repo grep + user refs → `_source/{web,repo,refs}/` + outline.md
    - `blogpost-research-reviewer.md` — MORE_NEEDED/OK 판정 (3+ 웹 자료 / outline 섹션별 source 인용 / refs 매칭 검사)
    - `blogpost-image-curator.md` — Unsplash > Pexels > Wikimedia Commons CC 라이선스 강제 + curl 다운로드 + metadata.json["images"] 매핑
    - `blogpost-writer.md` — `_source/` + outline + images → `초안.md` (한국어/토픽 언어, 인라인 인용, 이미지 마크다운 참조, TODO 마커로 gap 표시)
    - `blogpost-writing-reviewer.md` — RESEARCH_GAP/IMAGE_GAP/OK 판정 (인용 누락 / 이미지 미배치 / 품질 검사, iteration cap 5)
    - `blogpost-html-renderer.md` — `초안.md` → `_render/body.html` + `_render/toc.json` (figure/figcaption + callout + section id slug 부여)
  - **2 commands** (`commands/`):
    - `create.md` — Phase 0(settings) → Phase 1(folder name AskUserQuestion) → Phase 2(skeleton mkdir) → Phase 3(research loop) → Phase 4(image curation) → Phase 5(write+review loop) → Phase 6(html render) → Phase 7(S3 sync) → Phase 8(report)
    - `update.md` — sync down → AskUserQuestion(편집 끝났는지) → 재렌더 → AskUserQuestion(업로드 확인) → sync up
  - **scripts/render.py** — Jinja2 layout wrapping driver. `_render/body.html` + `_render/toc.json` + `metadata.json` → `index.html`. markdown→HTML 변환 안 함.
  - **scripts/sync_s3.sh** — `up` / `down` 두 모드. `~/.claude/blogpost.local.md` frontmatter 파싱 (awk + sed) → bucket/prefix 추출 → `aws s3 sync` 실행. `_render/`, `_source/`, `review-history/`는 업로드 제외. workspace 기본 `~/blog/` (`BLOGPOST_WORKSPACE` env로 override).
  - **scripts/test_fixture/** — 1x1 transparent PNG + sample 초안.md + metadata.json + 사전 렌더된 _render/{body.html,toc.json}. `python scripts/render.py scripts/test_fixture` 한 줄로 스모크 테스트 가능.
  - **templates/blog.html.j2** — 좌측 floating sticky TOC sidebar (240px) + 본문 (max 720px) + figure styling + 3색 callout (note/warn/tip) + 모바일 single-column 반응형. 외부 CSS/JS 의존 없음.

- blogpost plugin은 opt-in. 활성화하려면:

- 의존: `aws CLI` (sync), `curl` (이미지 다운로드), `python3 + jinja2` (render). 부재 시 명확한 에러 메시지로 안내

### Why this matters

- **CC 라이선스 강제**: 사용자가 가장 쉽게 실수하는 부분(저작권 미확인 이미지)을 image-curator의 hard rule로 차단. 라이선스 미명시 이미지는 사용 금지, 출처 metadata.json 기록 필수, 빈 섹션은 그냥 비워둠
- **자료 미비 → 글 쓰지 않음**: writing-reviewer의 RESEARCH_GAP 판정으로 "자료가 없어도 그럴듯하게 써버리는" 실패 모드 차단. researcher/image-curator로 회귀 후 재작성
- **markdown 1:1 변환 금지**: html-renderer가 figure/figcaption/callout/section semantics를 적극적으로 부여 → 결과물이 raw markdown dump가 아니라 visually 블로그 형태
- **round-trip 단순성**: `aws s3 sync`만으로 update 워크플로우 성립. 별도 versioning / merge 로직 없이 사용자 의도(폴더째 가져와 편집 후 재업로드) 충실 반영
